# 当前进度

## 已实现

- 最小 Go2 有线通信、原生 ROS 遥测与显式控制接口；默认禁止运动。
- D455/X3 独立采集；C++ RGB-D 压缩；相机标定与 TF 的单一职责。
- 独立话题录制与纯话题回放，统一 data/bags/ 输出；回放生成 /clock。
- 独立 C++ 压缩入口，检测回放时钟并复用已有压缩输入；XNavDP 使用观测时间戳并等待输入就绪。
- 独立 XNavDP health/点目标请求/trajectory+result 校验；与服务端保持同一协议，不执行运动。
- 已移除算法托管与图像解码转发遗留，基座只负责本体通信。
- 参数分层、独立环境与统一 `sh/setup/install.sh` 安装检查入口；基座实现归 `dimos/core/`，构建和版本约束归 `sh/dependencies/`，低频脚本归入子目录。
- 独立 RViz 视图沿用 XNavDP 显示样式，trajectory/result 直连，点云与 TF 辅助仅在可视化入口启用。
- 独立 path_tracker 订阅原生结果/odom/深度；使用 MPC 与碰撞检查，默认终端速度预览。默认安装准备跟踪依赖。
- VLM 默认由调用进程直连 DashScope，原生 HTTP 配置可选。VLM、LLM、主 Agent 和 Web 支持独立文件测试，提供显式期限、队列、取消和配置检查。
- `dimos/vln_task/` 作为独立上层，统一组织 CLI/Web、LLM/VLM、RGB-D 观测、XNavDP 和 tracker；基础插件保留独立输入输出。
- Web 启动时准备相机缓存、XNavDP ROS 端点和 Ollama 模型预热，按阶段记录等待与请求耗时。
- 找物由 VLN Task 先检测当前画面；默认实机 Shell 入口启用记忆与前沿探索，未启用记忆的 motion 装配按 60° 间隔原地扫视。有框但深度无效时，用 RGB-D 局部地图选择沿框方向的安全短目标，停车后复检；回放从录制数据获取新视角。
- 实机 profile 在 Web 进程内持续为当前任务的探索点或接近点规划，将校验通过的路径交给 tracker。到达或取消时停止，速度经原生 `/cmd_vel` 送往 Go2 基座。
- 独立日志终端记录实际启动的模块、Agent 调用与 tracker 速度状态，支持实机和 bag 会话。
